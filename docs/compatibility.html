Dependency clarity

Verified requirements

Address Library is a requirement, not a repaired plugin.

The supplied all-in-one v2 archive included versionlib-1-512-105-0.bin. Its presence was verified during the Game Settings Loader test, but it is not counted as a second OBSE64 plugin repair. UNBSE rejects an address-library-dependent plugin when the matching runtime table is absent, rather than executing relocation-dependent code without its required data.

Retail evidence

What the completed test proved

  • The original failure was REL/Trampoline.cpp(101): cannot create a trampoline with a zero size.
  • Game Settings Loader requested trampoline support without reserving bytes.
  • UNBSE now treats a zero-byte branch-pool allocation as a non-consuming request for the current pool cursor, matching the legacy OBSE64 contract.
  • The retail log reported exact runtime-anchor verification, compatibility verified, plugin loaded, trampoline available, and zero load failures.
  • The plugin parsed one INI setting and logged fJumpHeightMin = 64 -> 128, then 64 -> 256 on a second launch.
  • The larger jump was observed in game, DataLoaded fired, and the test session completed without the startup crash.

Evidence level: supervised local retail in-game proof. Raw logs and test fixtures remain outside the public release contents.

Promotion gate

Checklist for each future plugin

  • ☑ Record the exact game, plugin, and requirement versions.
  • ☑ Reproduce the original failure before changing UNBSE.
  • ☑ Keep the repair bounded to the legacy interface behavior the plugin uses.
  • ☑ Verify query, load, required messages, and trampoline behavior as applicable.
  • ☑ Exercise at least one visible or logged plugin feature in the retail game.
  • ☑ Confirm zero load failures and no crash during the supervised test.
  • ☑ Publish only the compatibility result and production change—not raw captures or proof fixtures.
