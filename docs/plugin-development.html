Build a native UNBSE plugin

A native add-on is a 64-bit Windows UE4SS C++ mod that registers with the UNBSE host. The public boundary is a C ABI, so the add-on can be built and released independently from UNBSE.

Current runtime: UNBSE 0.11.0-rc.1 supports the Steam game executable version 1.512.105.0 only. Check runtime identity before using version-specific addresses or behavior.

1. Include the SDK

Add the UNBSE SDK headers to your project. Begin with UNBSEAddonHostV1.h; it also brings in the script-service declarations. The remaining services are optional.

HeaderUse
UNBSEAddonHostV1.hRegistration, capabilities, ownership, and retirement
UNBSEMessagingV1.hIn-process messages and lifecycle events
UNBSEScriptServiceV1.hNative functions exposed to supported script runtimes
UNBSERuntimeInfoV1.hLoaded executable and foundation identity
UNBSERelocationV1.hOwner-checked executable RVA resolution

2. Find and register with the host

Locate UNBSE_QueryAddonHostV1 among the modules already loaded in the game process, request ABI version 1, then submit a descriptor. Use a stable, namespaced add-on ID and declare every effect your add-on can perform. 

#include <UNBSEAddonHostV1.h>
#include <cstdint>
#include <cstring>

bool RegisterAddon(UNBSEQueryAddonHostV1Function query,
                   UNBSEAddonHostV1& host,
                   std::uint32_t& owner)
{
    host = {};
    host.structSize = sizeof(host);
    if (!query(UNBSE_ADDON_HOST_ABI_VERSION, &host)) {
        return false;
    }

    UNBSEAddonDescriptorV1 descriptor{};
    descriptor.structSize = sizeof(descriptor);
    descriptor.apiVersion = UNBSE_ADDON_HOST_ABI_VERSION;
    descriptor.declaredEffects = UNBSE_ADDON_EFFECT_RUNTIME_READ;
    descriptor.requiredHostCapabilities =
        UNBSE_ADDON_HOST_CAPABILITY_RUNTIME_INFO_V1;
    std::memcpy(descriptor.addonId, "example.weather", 16);
    std::memcpy(descriptor.addonVersion, "1.0.0", 6);

    UNBSEAddonRegistrationV1 registration{};
    registration.structSize = sizeof(registration);
    registration.apiVersion = UNBSE_ADDON_HOST_ABI_VERSION;
    if (host.registerAddon(&descriptor, &registration) !=
        UNBSE_ADDON_RESULT_OK) {
        return false;
    }

    owner = registration.ownerHandle;
    return true;
}

Keep the host table and returned owner handle for the add-on lifetime. Check missingHostCapabilities before using optional features.

3. Query only the services you use

Each service has its own query export and ABI version. Initialize structSize, request the matching version, and verify returned function pointers before calling them. Runtime-info and relocation queries are independent exports; the add-on host provides the script-service query.

4. Retire cleanly

Stop new work, release listeners or callbacks owned by the add-on, then call host.retireAddon(owner, deadlineMs). Message payloads and script call pointers are borrowed only for the synchronous call unless a header says otherwise.

5. Package the add-on

Ship the DLL as an enabled UE4SS C++ mod under ue4ss/Mods/<YourPlugin>/dlls/main.dll. Do not place a native UNBSE add-on in OBSE/Plugins; that directory is for plugins using the OBSE64 compatibility ABI. State the UNBSE and game versions you support.
